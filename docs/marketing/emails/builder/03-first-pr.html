Last one for now — how to jump in.

If you write code, the good first issue label is the fastest way in. Test coverage for the lookup sources is a great first contribution: you learn the codebase without changing behavior, and the seams make it straightforward. Clone, make check, pick an issue, open a PR — I review fast.

If you don't write code, issues and Discussions are wide open. "Would you ship X?" is a valid issue. "This UX is confusing" is a valid issue. The half-baked thought in your head is the one I most want to hear.

Where it's headed: the current line is an honesty pass across every screen that explains the app, then a v1.9 workspace rethink — collections, wishlists, and saved searches as first-class things. The committed roadmap is in docs/roadmap.md, and the loose ideas are in Discussions.

That's it from the welcome side — from here I'll only write when a real version ships. Hope to see a PR from you.
